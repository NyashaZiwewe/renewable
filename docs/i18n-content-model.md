# Internationalisation and Content Model

This static build uses Portuguese as the default language and English as a secondary language.

## Static UI Strings

Interface strings live in one JSON file per locale:

- `locales/pt/common.json`
- `locales/en/common.json`

Use stable keys such as `nav.contact`, `actions.requestAssessment`, and `forms.phone`; do not use full sentences as keys. The generated pages are server/static-rendered from these files so each locale can be indexed independently. The client script loads only the active locale JSON and leaves the rendered text in place if a key is missing.

The generated header and footer are shared per language:

- `pt/header.html`
- `pt/footer.html`
- `en/header.html`
- `en/footer.html`

Pages mount the matching language partial through `js/site-i18n.js`. Page-specific state, such as the active navigation item and the equivalent language-switch URL, is stored on the page's `body` element.

When the files grow, split them by page or feature, for example:

- `locales/pt/common.json`
- `locales/pt/home.json`
- `locales/pt/contact.json`
- `locales/en/common.json`
- `locales/en/home.json`
- `locales/en/contact.json`

## URL Structure

Current static URLs use locale prefixes:

- Portuguese: `/pt/...`
- English: `/en/...`

Each generated page includes:

- `html lang`
- canonical URL
- `hreflang="pt"`
- `hreflang="en"`
- `hreflang="x-default"` pointing to Portuguese

The sitemap is generated by `scripts/generate-site.mjs`. Set the real production domain when generating it:

```bash
SITE_BASE_URL="https://your-domain.example" node scripts/generate-site.mjs
```

## Dynamic Articles

Future articles should not be stored in locale JSON files. Use database tables with one parent article and one row per translated version:

```sql
CREATE TABLE articles (
  id BIGSERIAL PRIMARY KEY,
  author_id BIGINT NOT NULL,
  published_at TIMESTAMPTZ,
  status TEXT NOT NULL CHECK (status IN ('draft', 'published', 'archived'))
);

CREATE TABLE article_translations (
  id BIGSERIAL PRIMARY KEY,
  article_id BIGINT NOT NULL REFERENCES articles(id) ON DELETE CASCADE,
  locale TEXT NOT NULL CHECK (locale IN ('pt', 'en')),
  slug TEXT NOT NULL,
  title TEXT NOT NULL,
  excerpt TEXT,
  body TEXT NOT NULL,
  meta_description TEXT,
  UNIQUE (article_id, locale),
  UNIQUE (locale, slug)
);
```

Recommended behaviour for missing translations: hide untranslated articles from the English listing. If a user lands directly on a missing English translation, show the Portuguese article with a clear notice or redirect to the Portuguese URL.

## Language Choice

Portuguese is the default. The language switcher links to the equivalent page in the other language and stores the user's explicit choice in `localStorage`. Avoid redirecting crawlers based on language detection.

## Locale Decisions

The current Portuguese copy targets Mozambican Portuguese conventions. Before launch, have the Portuguese and English copy professionally reviewed, especially product, warranty, legal, and supplier language.
